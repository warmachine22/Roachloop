WHY ROACH LOOP

Your project should remember more than your chat does.

01

Build without being a developer

Describe what you want. Your coding agent handles implementation while Roach Loop gives the work structure, checkpoints, and verification.

02

Switch agents without starting over

Use Claude Code today, Codex tomorrow, and a newer model next month. Project context lives in the repo instead of being trapped in one conversation.

03

Stop feeding the whole history back

Roach Loop compiles focused context for the task at hand. Agents spend their context window on the work—not rereading every conversation that came before.

THE OTHER HALF

When an AI says “done,” Roach Loop asks for proof.

Coding agents are excellent builders. They are not reliable sources of truth about their own work. Roach Loop runs verification, records evidence, detects stale proof after code changes, preserves review history, and keeps the human in charge of product intent.

Intent→Requirements→Build→Verify→Evidence→Human

PORTABLE BY DESIGN

The agent is replaceable.
The project memory isn't.

Requirements, checkpoints, decisions, redirects, findings, verification receipts, reviews, and current state travel with the repository. A new agent can ask Roach Loop what matters next instead of depending on a previous model's memory.

$ python3 scripts/roach.py next
CP-014 — Checkout flow
Status: implementing
Risk: high
Requirements: FR-021, QR-008
Next: verify CP-014
