HOW IT WORKS

Proof-carrying development for coding agents.

Roach Loop separates intent, implementation, evidence, and judgment so no single model is the source of truth.

1. Intent becomes requirements

Stable IDs keep product intent traceable to checkpoints and evidence.

2. Context is compiled

roach context CP-014 --role worker emits only what that role needs. Reviewer and auditor packets stay isolated from builder reasoning.

3. Verification creates receipts

Roach executes the declared command and records the exact Git tree, exit code, timestamps, and output hashes. Behavior cannot pass by editing JSON.

4. Gates are a state machine

Behavior, adversarial review, human acceptance, and audit cannot be skipped. Invalid transitions are rejected.

5. Proof can become stale

Change the Git tree after verification and old behavior evidence is no longer current.

6. History is tamper-evident

Managed events are hash-chained. verify-project validates the chain without an AI model.

7. Work is sealed, not merely called done

A seal requires current evidence, traceability, and the gates demanded by the assurance profile.

What still requires judgment?

Humans remain authoritative on product intent and acceptance. Models remain useful for architecture, adversarial, UI, and semantic review. Roach verifies the surrounding facts and provenance.
