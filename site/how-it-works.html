HOW IT WORKS

Your AI does the work.
Your project keeps the memory.

Roach Loop separates what you want, what the agent changes, and what has actually been proven.

01

You describe the product

Roach Loop turns durable intent into requirements and checkpoints. You remain the authority on what the product should do.

02

The agent gets only the context it needs

Instead of replaying a giant chat, the agent can load a focused worker, reviewer, or auditor context packet for the current checkpoint.

python3 scripts/roach.py context CP-014 --role worker
03

The agent builds

Claude Code, Codex, or another coding agent can implement the checkpoint. Roach Loop is not tied to a specific model.

04

Roach Loop verifies

Declared tests and tools execute for real. Evidence records the code state, command, result, environment, and hashes. Relevant code changes make old proof stale.

05

Reviews stay independent

Semantic and adversarial review carry reviewer provenance instead of becoming an untraceable “looks good.” Findings have a lifecycle.

06

You decide whether it feels right

Roach Loop does not replace human product judgment. Human acceptance is explicit and tied to the artifact being accepted.

07

The next agent picks up the project

The durable state is in the repository. Switch models, start a fresh chat, or come back later. Run roach next and continue from recorded state.

What Roach Loop does not claim

It doesn't magically prove software has zero bugs, and it doesn't replace your judgment. It makes the assurance process explicit, reproducible, tamper-evident, and portable across agents.
